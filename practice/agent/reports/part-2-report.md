Дата эксперимента: 10 ноября 2026 года. В приложение добавлены 30 задач командой `seed.py 30` через порт 5001; предыдущие задачи сохранены. На момент эксперимента в API было 364 задачи: 118 выполненных и 246 невыполненных, в том числе 45 просроченных невыполненных. Приоритеты: high — 125, normal — 115, low — 124. Просрочка — срок раньше даты отчёта, при условии что задача не выполнена.

## Задание и условия

Три независимые сессии Qwen Code 0.27.1 с моделью `agentic/gc_v3` получили одинаковую просьбу: создать Excel-файл со списком всех задач и сводкой по приоритетам, статусам, проценту выполненных и числу просроченных. Отличались только каталоги результатов. Агентам разрешили получать задачи только через MCP `list_tasks`, не менять задачи, не устанавливать пакеты и не обращаться напрямую к сети. Им указали, что в `/Users/lendwye/anaconda3/bin/python` уже доступен `openpyxl`; это важное условие эксперимента — он не измеряет стоимость установки зависимости с нуля.

Вместо интерактивной команды `/export` полная потоковая история каждой сессии сохранена Qwen непосредственно в отдельный файл `trajectory.jsonl` в каталоге соответствующего запуска. В ней видны действия, вызовы и результаты инструментов. `stderr.log` содержит диагностический вывод. Лимит на каждый запуск — 480 секунд.

### Ход работы и различия

- **Запуск 1.** Агент запросил полный список, написал `build_report.py` с использованием доступного `openpyxl` и запустил его. Сначала ошибочно принял сохранённый результат MCP за JSONL, затем исправил разбор многострочных JSON-объектов и повторил запуск. Проверил файл и число просроченных отдельным вызовом MCP. Итог: `run1/report.xlsx`.
- **Запуск 2.** Агент сам ограничил первый запрос 100 задачами, затем запросил выполненные и невыполненные отдельно. Невыполненные он взял из сохранённого вывода, а выполненные перенёс в код вручную. Исправил ошибку формата JSON и ошибку использования `openpyxl`, после чего получил файл. При сверке приоритетов обнаружил расхождение и пытался найти причину, но сессия превысила лимит. Независимая сверка выявила **14 несовпадений полей** со значениями API: в частности, приоритет задачи 234 и ряд сроков. Сводка показывает high=124 и normal=116 вместо 125 и 115. Файл `run2/report.xlsx` сохранён как результат опыта, **для работы с данными его использовать нельзя**.
- **Запуск 3.** Агент также начал с явно указанного лимита 100, затем запросил все 364 задачи с `limit=1000`. Использовал отдельные счётчики MCP для проверки, несколько раз экспериментировал с разбором сохранённого вывода и написал `build_report.py`. Получился файл `run3/report.xlsx`; лист сводки содержит перекрёстную таблицу приоритетов и статусов.

Скрипты агентов зависят от временных файлов результатов Qwen в `~/.qwen/tmp`, поэтому их нельзя считать готовым воспроизводимым решением: временные файлы могут исчезнуть. Ни один запуск не устанавливал библиотеки — это было явно запрещено в задании агентам.

## Независимая проверка файлов

Через `openpyxl` проверены листы, количество строк и все пять полей каждой задачи по сравнению с `GET /api/tasks`: ID, название, приоритет, срок и статус. Каждый файл содержит 364 уникальных ID, пропусков нет. У запусков 1 и 3 расхождений нет, у запуска 2 — 14 расхождений полей. Сводные показатели также просмотрены отдельно: файлы 1 и 3 соответствуют контрольным значениям; во втором неверны количества high и normal. Полученные таблицы сгенерированы на указанную дату и при изменении задач автоматически не обновляются.

## Как упростить работу агенту

1. **Готовый MCP-инструмент экспорта:** например, `export_tasks_xlsx` получает данные программно, единообразно строит листы и возвращает путь к файлу и показатели. Ему нужны чёткие правила выбора пути, защиты от перезаписи и прав доступа. Такой инструмент избавит модель от разбора больших текстовых результатов и повторного написания скрипта.
2. **Skill с проверенным скриптом:** сохранить инструкцию, шаблон, зависимости и протестированный генератор, а агенту передавать только параметры отчёта. Skill упрощает повторение процедуры, но сам по себе не гарантирует надёжного доступа к данным: скрипту нужен явный, разрешённый источник, а не временный файл Qwen.

В обоих вариантах стоит получать данные структурированно, не переносить их вручную в код, сравнивать число записей с источником и тестировать сводные расчёты. Реализация отдельного Excel MCP-сервера или skill в этой части не требовалась; здесь приведены варианты улучшения.
